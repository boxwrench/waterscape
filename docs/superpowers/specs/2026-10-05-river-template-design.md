# River Pulse river template and modular structure

Status: approved in conversation 2026-10-05 (approach B, staged, aggressive). The user waived
line-by-line review; their one hard requirement is that no 3D data or model is lost.

## Goal

A tidy, hierarchical, modular River Pulse that a new contributor can read once, copy to make
their own river, and extend with an AI collaborator. Russian River is the reference river.

## The template

Every river has a **river map view** and **3-4 scene slots**:

| Slot | Meaning | Russian reference |
|---|---|---|
| `start` | Headwaters or upper river | East Fork (Lake Mendocino area), **planned** |
| `middle` | The scenic middle | Hacienda Bridge (Map / Bridge / Hacienda Beach) |
| `end` | Mouth or lower river | Jenner Estuary (Estuary lookout / River shore / Pacific beach) |
| `extra` | Optional fourth scene | none |

Each scene has a few **views** (fixed cameras). A slot with no scene yet is a **planned**
placeholder: it blocks out structure, shows an honest "planned" card, and carries no invented
content. Slot assignments are editorial and recorded per river.

**Data tiers** say what a scene may show; richer data raises fidelity without changing
structure: 0 geography only, 1 live gauge, 2 history and condition context, 3 fine terrain
(lidar). The visual language is shared; a scene's tier decides which data components it uses.

## Folder structure

```
river-pulse/
  README.md  index.html  river.html  registry.json (generated)
  app/        atlas and river-home pages (app/data/ = state overview)
  core/       adapters, data-model, visual-bindings: no DOM, no 3D
  scene-kit/  shared 3D: terrain, water, materials, centerline
  ui/         shared tokens and scene chrome
  rivers/<river>/
    river.json  README.md
    scenes/<slot>/<place_id>/
      scene.json  index.html  <scene code>  thumb.jpg
      data/       place.json, terrain, hydrography, setting/ ...
```

A file lives in `scene-kit/` if two or more scenes import it, otherwise in its scene folder.
`core/` stays generic. Place id equals its folder name and `river_pack` equals the river
folder, as before; the registry is generated by globbing `rivers/*/scenes/*/*/data/place.json`.

## Safety net (3D data)

1. Tag `pre-restructure-2026-10-05` is the restore point.
2. A SHA-256 inventory of every file under `river-pulse/` is taken first and committed. After
   the move, every hash must exist at a new path, and the move script rewrites references
   rather than editing content. Files are moved with `git mv`, so history follows them.
3. Anything that does not fit goes to `archive/` inside the river-pulse tree, never deleted.
4. Unit tests, build, and browser captures of all five scenes are compared before and after.
